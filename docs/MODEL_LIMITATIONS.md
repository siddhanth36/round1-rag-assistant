# Model Limitations — BIT-PLATE-CV-1.0

The Round 2 inspection model is supplied, frozen and used unchanged. This page records what it is, what was
measured, and why that measurement does not make it a production inspection tool.

## 1. What the model is

| Item | Value |
|---|---|
| Model name / version | `BIT-PLATE-CV-1.0` (supplied by Blessed IT Solution Pvt Ltd, Round 2 pack v1.0) |
| Product | `P-PLATE01`, Demonstration metal plate (fictional) |
| Type | Frozen, pretrained **logistic-regression** binary classifier (not a neural network) |
| Input features | **17** numerical image features: mean and standard deviation of intensity; 8 quantiles of median-centred intensity; 5 dark-pixel fractions; mean adjacent-pixel difference on each axis |
| Classes | `Normal` (0), `Defective` (1); Defective when `defect_probability >= 0.5` |
| Training (per supplier) | 1,200 procedurally generated images, 600 per class. Not retrained or modified by this team |
| Files | `inspection_ai/model/` (copied byte-for-byte; verified with `verify_model_integrity()`) |

**Fixed preprocessing and framing.** Every image goes through the supplied pipeline in `inference.py`: EXIF
orientation → RGB → resize to 128×128 (bilinear) → grayscale → centre crop of rows/columns 16–111 → ÷255. The
crop assumes the plate is centred against a dark border, exactly as in the supplied images. Fixed framing is part
of the model contract: rotated, displaced or differently framed products are outside its validated scope.

The model outputs only Normal/Defective. It does not identify defect type, location, size, severity or cause.

## 2. Measured result on the supplied samples

Run with `python -m inspection_ai.evaluation <Samples dir> <Samples/labels.csv>` on the 60 official images
(checksums verified against the pack's `SHA256SUMS.txt`). Defective is the positive class.

|                  | Predicted Normal | Predicted Defective |
|---|---|---|
| **Actual Normal** (30)    | TN = 30 | FP = 0 |
| **Actual Defective** (30) | FN = 0  | TP = 30 |

- Defect recall = TP / (TP + FN) = 30 / 30 = **1.0000**
- Failed predictions: 0 of 60
- `defect_probability` range — Normal samples: **0.013–0.204**; Defective samples: **0.799–1.000**

No false negatives occurred on this set.

## 3. Why 60/60 does not establish real-world reliability

- **The samples are synthetic.** All 60 images are procedural illustrations generated by the same kind of
  process as the training data, not photographs of manufactured parts. Matching the generator is not the same
  as matching a factory.
- **The sample is small.** With 30 defective images and 0 misses, the data cannot rule out a substantial
  real-world miss rate. (By the standard "rule of three", 0 failures in 30 trials is still consistent with a true
  miss rate of up to about 10% at 95% confidence.)
- **The samples are development data, not a blind benchmark.** They are the set the team has seen.
- **Scores are uncalibrated.** `defect_probability` and `confidence` are raw model outputs. A value of 0.95 does
  not mean a 95% chance the part is defective, and the wide margins seen above say nothing about how scores
  behave on unfamiliar images.
- **Only one product and two defect kinds** (simulated scratches and pits) are represented.

## 4. Conditions that would likely change results

None of these are covered by the supplied data:

- **Lighting:** intensity, colour temperature, glare, reflections, shadows.
- **Camera:** sensor, lens, focus, resolution, compression, noise, exposure.
- **Positioning and framing:** rotation, offset, scale, perspective, a background other than the dark border.
  The fixed centre crop makes the model sensitive to these.
- **Surface condition:** oil, dust, finish variation, markings, wear that is not a defect.
- **Production environment:** other products or variants, new defect types, vibration and motion blur, line
  speed.

## 5. Recommendation before any production use

1. Collect a representative set of real images from the target line, camera and lighting, labelled by qualified
   inspectors, kept separate from anything used to tune the system.
2. Measure recall, false-positive rate and failure rate on that set with the same evaluation module, and set an
   acceptance threshold with the quality team before deployment.
3. Check score calibration on real data before showing `confidence` as anything more than a model score.
4. Keep supervisor review in the loop and monitor review corrections as an ongoing measure of model error.
5. Re-validate whenever the camera, lighting, fixture, product or process changes.

Until then, BIT-PLATE-CV-1.0 is an educational demonstration for the hackathon, not a validated inspection
system.
